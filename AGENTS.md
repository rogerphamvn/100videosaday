# Repository working agreement — 100videosaday

Applies only to `https://github.com/rogerphamvn/100videosaday` and its working copy.

## Standing owner authorization — 20/10/2026

The owner requested: “đẩy toàn bộ lên github này nhé … làm xong tự merge vào, nhớ ghi changelog … các lần làm tiếp theo mỗi lần làm xong tự merge lên”.

For owner-requested work in this repository:

1. Finish the scoped change and review the actual diff and relevant artifacts.
2. Update `CHANGELOG.md` with changes, fixes, verification and material limits. Planned AI/provider/render functionality must not be described as implemented.
3. Run relevant checks and repository CI. Fix failures before merging; respect branch protection and required checks/reviews.
4. Commit to a task branch, push, open/update a pull request, and merge into the default branch when ready and required checks pass. The owner has authorized these routine GitHub actions; no repeated approval pause is needed.
5. Verify remote merge state and commit SHA; report PR/commit and any remaining gap.

This authorizes completed requested work, not unrelated PRs, force-push, deletion of remote data, changing repository security, production deployment, advertising publication or API credit spend. It creates no scheduled automation. If credentials/protection/checks block an action, report the exact blocker; never claim a merge that did not happen.

## Product and evidence boundaries

- Real product sources and owner-confirmed facts outrank creative inference. Keep facts, customer evidence, hypotheses, demo data, generated output and observed performance distinct.
- Canonical mega/negative JSON is versioned; provider adapters compile documented fields. Never commit credentials or expose keys in the browser.
- Spatial UI illustrates lineage, not a product mesh or physical simulation. Preserve planar controls and list/keyboard alternatives.
- Taste learning means scoped, versioned evidence/preferences with evaluation and rollback, not model-weight training. Self-scores cannot approve their own new rule.
- Do not promote prototype controls or architecture docs into runtime/deployment claims.

## Change safety

Preserve contributors' edits/history, fetch before publishing, and reconcile concurrent changes. Keep local Hub/memory/harness records, machine-specific helper scripts and duplicate ZIP bundles out of Git. Apply global operating rules where relevant; directly invoked Astra work requires actual dispatch and version-bound review, not role labels.
